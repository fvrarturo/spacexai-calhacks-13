04.1 / THE PIPELINE

Archive in.
Evidence out.

The same four steps for every analysis. Raw data stays on the cluster; the site renders compact result files that anyone can regenerate.

01 / ACQUIRE

Mirror the archive.

Bulk downloads run as data-transfer jobs into cluster scratch. We record the source, version, access date, size and record count.

02 / PROCESS

Shard and parallelise.

Slurm job arrays parse archives in independent shards and write columnar tables. Every job ID, partition and runtime is kept with the result.

03 / ANALYSE

Count the right units.

A protein, a run or a satellite is the unit of evidence, not a frame or a row. Matched comparisons, bootstrap intervals and stated confounders come before any headline.

04 / PUBLISH

Small, honest files.

Each analysis writes one JSON result: question, headline, charts, findings, limitations, next steps and the commands to reproduce it. The site reads those files directly.

LABELMEANINGWHAT IT CAN SUPPORT
Published resultA value taken from a peer-reviewed paper or agency document, with the page or table cited.That someone measured it, under their conditions.
Our computation on public dataWe downloaded the data and computed the value with our code.A pattern in the archive. Not, by itself, a causal effect of microgravity.
Physics computationA calculation from standard physical laws with stated inputs.Orders of magnitude and design bounds, not measurements.
SimulationA seeded model with stated assumptions.When a policy helps or hurts inside the model. Not flight performance.
HypothesisSomething we intend to test.A reason to run an experiment.

Python data stackStreaming parsers, Parquet tables and NumPy/pandas statistics. The libraries for each analysis are in its methods note and requirements.
